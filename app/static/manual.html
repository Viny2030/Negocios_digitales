1. Qué es

Una API para empresas con tres productos de optimización. Cada empresa tiene su propia clave y sus datos quedan separados de los de las demás.

ProductoPara qué sirveQué hay que mandarle
DynamicPricingRecomendar el precio de cada productoCosto, precio actual e historial de ventas, en cada pedido
SmartRoutePlanificar el reparto de una flotaDepósito, paradas con horario y vehículos, en cada pedido
LeadMatchAsignar cada lead al vendedor más convenienteLeads y vendedores; opcionalmente, un histórico para entrenar un modelo propio

Los ejemplos usan http://localhost:8000: reemplazalo por la dirección donde esté instalada la API. La referencia completa de cada campo está en /docs.

2. Primeros pasos

Registrar la empresa

curl -X POST http://localhost:8000/api/v1/companies \
  -H "Content-Type: application/json" \
  -d '{"name": "Empresa Demo", "contact_email": "demo@empresa.com"}'

La respuesta trae el campo api_key.

Guardá la clave en ese momento. Se muestra una sola vez, porque la plataforma guarda únicamente una huella que no permite recuperarla.

Usar la clave

Mandala en el header X-API-Key de cada pedido:

curl http://localhost:8000/api/v1/companies/me -H "X-API-Key: TU_CLAVE"

Cambiar la clave

Si creés que se filtró, generá otra. La anterior deja de funcionar en el momento, así que actualizá tus sistemas enseguida.

curl -X POST http://localhost:8000/api/v1/companies/me/rotate-key -H "X-API-Key: TU_CLAVE"

Para generar una nueva hace falta la clave vigente. Si la perdiste, tiene que intervenir quien administra la plataforma.

3. Cómo funciona

Todo pedido pasa primero por cuatro controles, en este orden. Después sigue por una de las cinco líneas, según la ruta que se llamó.

  • Entrada
  • Control
  • Ruta de la API
  • Proceso
  • Dato guardado
  • Respuesta

Cómo leer el grafo

  • Controles (fila superior): frenan el abuso antes de gastar recursos y comprueban la clave. Si uno falla, el pedido termina ahí con un error (ver Límites y errores).
  • DynamicPricing y SmartRoute: calculan todo con lo que llega en el pedido y no guardan nada.
  • Carga de datos y Entrenamiento: son opcionales y solo sirven a LeadMatch. El archivo subido alimenta a la regresión logística, que produce una versión nueva en el registro de modelos.
  • LeadMatch: usa el modelo vigente de la empresa. Si todavía no hay ninguno, puntúa con una fórmula de respaldo y lo avisa con used_default_scoring: true.

4. Qué datos maneja

La plataforma guarda solo los datos de la empresa y lo necesario para LeadMatch. Lo que se envía a DynamicPricing, a SmartRoute y a /lead-match/match se usa para responder y se descarta.

Cómo leer el grafo

  • Empresa: de la clave se guarda solo la huella (api_key_hash) y sus primeros caracteres (api_key_prefix), que sirven para reconocerla.
  • Dataset y Archivo CSV: una empresa puede tener varios datasets. La tabla describe cada uno y el archivo queda en una carpeta propia de la empresa.
  • Columnas: el modelo aprende con cuatro columnas. lead_id y rep_id se aceptan en el archivo, pero no se usan para entrenar.
  • Versión de modelo y Versión vigente: cada entrenamiento agrega una versión, con sus métricas y el dataset que usó. current.json indica cuál se usa: una versión nueva solo pasa a ser la vigente si no es peor (ver LeadMatch).

5. DynamicPricing

Estima cuánto cambia la demanda de cada producto según el precio y busca el precio más conveniente dentro de tus reglas.

curl -X POST http://localhost:8000/api/v1/dynamic-pricing/price \
  -H "X-API-Key: TU_CLAVE" -H "Content-Type: application/json" \
  -d '{
    "skus": [{
      "sku_id": "sku-1", "base_cost": 100, "current_price": 150, "stock": 50,
      "min_margin_pct": 0.15, "max_daily_variation_pct": 0.10,
      "purchase_events": [
        {"price": 140, "quantity_sold": 30}, {"price": 150, "quantity_sold": 22},
        {"price": 160, "quantity_sold": 15}, {"price": 170, "quantity_sold": 9}
      ]
    }],
    "objective": "margin"
  }'
CampoSignificado
base_cost, current_priceCosto unitario y precio actual. Obligatorios.
purchase_eventsVentas anteriores: precio y cantidad. Hacen falta al menos 4 con ventas y 2 precios distintos para estimar la demanda.
stockUnidades disponibles: no se espera vender más que esto. Debe referirse al mismo período que purchase_events. Obligatorio.
min_margin_pctGanancia mínima sobre el costo. Por defecto, 0,15.
max_daily_variation_pctCuánto puede moverse el precio respecto del actual. Por defecto, 0,05.
competitor_price, max_competitor_premium_pctPrecio del competidor y cuánto por encima de él se puede vender. Por defecto, hasta 0,10 más. El margen mínimo y la variación diaria tienen prioridad.
objectivemargin busca la mayor ganancia esperada. volume, la mayor cantidad vendida; si el stock no alcanza, usa el precio más alto con el que igual se vende todo.

Cómo leer la respuesta

  • recommended_price: el precio sugerido.
  • used_default_elasticity: si es true, no hubo datos para estimar la demanda. Se mantiene el precio actual, ajustado solo si rompe una regla, y expected_quantity y expected_profit vienen vacíos. Sin stock también se mantiene el precio.
  • expected_margin_on_cost_pct: ganancia sobre el costo; es la que se compara con min_margin_pct.
  • expected_margin_pct: ganancia sobre el precio. Con costo 100 y precio 115, el primero da 15% y este, 13%.
  • constraints_applied: las reglas aplicadas. Si chocan, gana el margen mínimo, después la variación diaria y por último el competidor, y lo indica acá.

6. SmartRoute

Reparte las paradas entre los vehículos y define el orden de cada recorrido.

curl -X POST http://localhost:8000/api/v1/smart-route/plan-routes \
  -H "X-API-Key: TU_CLAVE" -H "Content-Type: application/json" \
  -d '{
    "depot": {"lat": -34.6037, "lon": -58.3816},
    "stops": [
      {"stop_id": "s1", "location": {"lat": -34.61, "lon": -58.38}, "demand": 5,
       "time_window_start_min": 0, "time_window_end_min": 240},
      {"stop_id": "s2", "location": {"lat": -34.60, "lon": -58.40}, "demand": 8,
       "time_window_start_min": 0, "time_window_end_min": 240}
    ],
    "vehicles": [{"vehicle_id": "v1", "capacity": 20}]
  }'

Los horarios se expresan en minutos desde el inicio del turno. Valores por defecto: 5 minutos por parada, 30 km/h y 480 minutos de duración máxima por ruta, incluido el regreso al depósito.

Cómo leer la respuesta

  • routes: para cada vehículo, sus paradas en orden, con llegada y salida, distancia, duración hasta volver al depósito y carga.
  • unassigned_stops: las paradas que no entraron en ningún vehículo por capacidad, horario o duración. Revisalo siempre y resolvé esas paradas de otra forma.

7. LeadMatch

Estima la probabilidad de que cada lead compre y lo asigna al vendedor que más suma, sin superar la capacidad de cada uno. Funciona desde el primer día; con tu histórico puede puntuar según tus propios resultados.

Paso 1 (opcional): subir el histórico

Archivo .csv, .tsv o .txt de hasta 25 MB. Se aceptan los CSV de Excel en español. Las columnas origin, time_on_site_minutes y company_size describen al lead; converted indica si compró (1/0, sí/no, yes/no o true/false).

curl -X POST http://localhost:8000/api/v1/datasets/lead_match \
  -H "X-API-Key: TU_CLAVE" -F "file=@leads.csv"

Paso 2 (opcional): entrenar

Hacen falta al menos 20 filas completas, con casos de 0 y de 1. Usá el id que devolvió el paso anterior.

curl -X POST http://localhost:8000/api/v1/lead-match/train \
  -H "X-API-Key: TU_CLAVE" -H "Content-Type: application/json" -d '{"dataset_id": 1}'

La respuesta incluye metrics.auc: 0,5 equivale a puntuar al azar, y cuanto más cerca de 1, mejor.

Entrenar no siempre cambia el modelo en uso. La versión nueva queda guardada, pero solo pasa a ser la vigente si su AUC llega a 0,55 y no es peor que el del modelo actual medido sobre las mismas filas. Mirá promoted y promotion_reason en la respuesta.

Paso 3: asignar

curl -X POST http://localhost:8000/api/v1/lead-match/match \
  -H "X-API-Key: TU_CLAVE" -H "Content-Type: application/json" \
  -d '{
    "leads": [{"lead_id": "l1", "origin": "paid_ads", "time_on_site_minutes": 22, "company_size": 300}],
    "reps": [{"rep_id": "r1", "capacity": 2}, {"rep_id": "r2", "capacity": 3, "specialties": ["paid_ads"]}]
  }'

Por vendedor podés indicar historical_close_rate (por defecto, 0,5) y specialties, que multiplican el puntaje por specialty_bonus (por defecto, 1,2).

Cómo leer la respuesta

  • assignments: lead, vendedor, probabilidad de compra y puntaje.
  • unmatched_leads: leads sin vendedor por falta de capacidad.
  • used_default_scoring: true significa que se usó la fórmula de respaldo en lugar de un modelo propio.

Ver las versiones y volver a una anterior

Para listar las versiones, con sus métricas y cuál está vigente:

curl http://localhost:8000/api/v1/lead-match/models -H "X-API-Key: TU_CLAVE"

Para dejar vigente una versión, ya sea una anterior o una que el entrenamiento no promovió:

curl -X POST http://localhost:8000/api/v1/lead-match/models/{version_id}/promote -H "X-API-Key: TU_CLAVE"

10. Limitaciones actuales

Conviene conocerlas antes de usar los resultados en una decisión real.

DynamicPricing

  • Estima la demanda solo a partir del precio: no considera temporada, promociones ni cambios del mercado. Con pocos eventos, la estimación es débil.
  • El competidor solo funciona como techo: no hace bajar el precio si ya estás por debajo de ese límite.

SmartRoute

  • Calcula en línea recta y a velocidad constante, sin calles ni tránsito: los tiempos reales serán mayores, así que conviene dejar margen en las ventanas horarias.
  • Busca una buena solución, no necesariamente la mejor posible. Una parada que figura sin asignar podría entrar con otra distribución de las rutas.
  • Todas las rutas salen del depósito al inicio del turno y hay un solo depósito.

LeadMatch

  • El modelo usa solo tres datos del lead: origen, tiempo en el sitio y tamaño de la empresa. No aprende del historial de cada vendedor: la tasa de cierre y las especialidades las informás vos.
  • Promover una versión no prueba que funcione bien con leads futuros: el AUC se mide con datos históricos.

Cuenta

  • El alta no verifica el email, y el error 409 permite saber si un email ya está registrado.

11. Instalación

Para quien instala la plataforma. Requiere Python 3.11.

pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app
  • Base existente: hacé un backup y corré alembic upgrade head antes de arrancar la versión nueva. Las claves emitidas siguen funcionando, pero esa migración no se puede revertir.
  • Detrás de un proxy o PaaS: definí TRUSTED_PROXY_HOPS (ver .env.example). Si no, todos los clientes comparten los límites por IP.
  • Archivos: los datasets y modelos se guardan en storage/. En un PaaS, montá ahí un volumen persistente o se perderán al redesplegar.
  • Varias instancias: los contadores de límites están en memoria de cada proceso. Para compartirlos hace falta un almacenamiento común, como Redis.
Referencia técnica de la API: /docs.
